## 语法点与"为什么要用它"的对应

读工程时最容易困惑的是"这里为什么这么写"，下表给出动机：

| 写法 | 动机 |
| --- | --- |
| X-Macro | 枚举、字符串、解析、合法性校验**四份数据必须一致**，手写必错；X-Macro 保证单一数据源 |
| `std::atomic<StateMachineType>` | 状态被 ROS2 回调线程和状态机线程同时读，用 atomic 免锁 |
| `Waiter` + `condition_variable` | 状态机要"睡到有任务为止"，不能用 `while(!flag) sleep` 轮询 |
| 服务回调只置标志 | 避免 ROS2 回调线程直接改状态机，造成数据竞争 |
| `tl::expected` | 嵌入式环境不希望异常传播，用返回值表达失败原因（`ErrorCode`） |
| 临时文件 + `rename` | 掉电时保证状态文件要么是旧内容要么是新内容，不会写一半 |
| `unique_ptr<FILE, deleter>` | `popen` 必须配 `pclose`，否则僵尸进程；RAII 保证异常路径也能关 |
| `void* userdata` + `std::function` | libcurl 的 C API 只能传裸指针，需要把闭包"装箱"再拆箱 |
| 状态类各自一个文件 | 18 个状态隔离编译，改一个状态不用重编全部 |

## 综合例程

`examples/ota_mini/` 把上面 16 个语法点**全部**用在一个小 OTA 里：

```
输入命令(模拟 /ota_local) → 任务标志 + 条件变量唤醒
   → 状态机(分发 map) → 各状态类(多态) → 线程池并行升级(15)
   → 原子写状态文件(10) → 结果用 Expected 返回(08) → 日志(09)
```

对着 `examples/ota_mini/README.md` 里的对照表，可以把每个文件直接映射回真实工程。
